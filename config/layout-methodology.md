# Weekly Report Board — Layout Methodology

이 문서는 주간보고용 이미지 보드를 합성할 때 적용하는 시각적 규칙을 정리한 것이다.
수치값은 `board-rules.json`에 정의되어 있으며, 이 문서는 "왜 그렇게 배치하는가"에 대한 판단 기준을 다룬다.

> ⚠️ 외부 공유용 보드 결과물에는 이 문서의 내용을 노출하지 않는다.
> 정적 HTML로 배포되는 동안에는 이 파일도 같이 배포되므로 완전한 비공개는 불가능하다.
> 완전 비공개가 필요해지면 이 문서를 서버 측 API 응답으로 옮기는 것을 검토한다.

---

## 1. 타입 분류 — aspect ratio 기준 3-tier

레이아웃 룰을 적용하기 전에 각 이미지를 aspect ratio(w/h)로 분류한다. 분류 임계값은 `image.classification`에서 관리한다.

| 타입 | 조건 | 의도 |
|---|---|---|
| `mobile` | aspect < `mobilePortraitMaxAspect` (기본 0.65) | 세로로 길쭉한 모바일 화면 캡처. 원본 비율 보호 우선. |
| `banner` | aspect > `wideBannerMinAspect` (기본 2.5) | 와이드 배너 / 히어로 / 가로 캡처. 단독 행으로 강조. |
| `standard` | 그 사이 (0.65 ≤ aspect ≤ 2.5) | 일반 사진, 가로 UI 캡처, 카드, 로고 등. justify 후보. |

타입은 행 단위 정렬 규칙(2번)을 결정한다.

## 2. 행 단위 정렬 — Justified row + 과확대 가드

- **기본 packing**: 모든 이미지를 `image.maxWidth`(300px)와 원본 폭 중 작은 값으로 1차 축소한 뒤, `canvas.width - canvas.padding*2`(=900px) 안에서 좌→우로 채워 행을 만든다. `banner`는 자동으로 단독 행을 갖는다.
- **Justify 조건** (행 단위로 판정):
  1. 행 내 모든 아이템이 `standard` 또는 `banner`다 (즉, `mobile`이 섞이지 않았다).
  2. 행 충진율(`행폭 / 900`) < `minRowFillRatio`(기본 0.85).
- **Justify 알고리즘**: 같은 높이 H로 모든 아이템을 통일해서 행 폭을 채운다.
  - 수식: `H = (900 - imageGap * (n-1)) / Σ(aspect_i)`
  - 안전장치:
    - `H ≤ maxRowHeight`(기본 420) — 1장 행이 과확대되는 것 방지.
    - `H ≤ min(naturalH_i)` — 어떤 아이템도 원본 해상도를 초과하지 않음. 행에 작은 로고가 끼어 있으면 행 전체가 자동으로 보수적으로 동작한다.
  - 캡 적용 결과 H가 원래 행 높이보다 작거나 같으면 justify를 건너뛴다 (가로 공백을 살짝 더 두는 게 낫다고 판단).
- **이유**: 300px 캡으로만 통일하면 가로 사진 2장이 620px만 채우고 280px가 빈다. 같은 행이 모두 사진이면 균등 스케일로 행 폭을 채우는 것이 자연스럽고, 모바일 캡처가 섞이면 모바일 비율을 보호하기 위해 자동으로 비활성된다.

## 3. 모바일 캡처가 섞인 행 — justify 비활성

- **기준**: `mobile`로 분류된 아이템이 한 장이라도 있는 행은 justify를 적용하지 않는다.
- **이유**: 모바일 캡처(375px 너비, aspect ≈ 0.46)를 900px에 맞추려고 늘리면 픽셀이 깨지고 의도한 비율이 무너진다. 이 경우엔 우측에 의도적 여백을 남기는 게 정직한 선택.
- **권장**: 모바일 캡처는 같은 섹션 안에서 모바일끼리 묶어 1~3열로 배치한다. 가로 사진과 섞으면 같은 행에 다른 비율이 와서 어색해진다.

## 4. 다크 배경 이미지 — 회색 보드 자동 wrap

- **기준**: 한 섹션 안에 "테두리가 검은" 이미지(예: 다크모드 UI 캡처, 검은 배경 사진, 다크 테마 코드 에디터 스크린샷)가 한 장이라도 포함되면, 그 섹션 전체를 회색 보드(`flowBoard.background` = `#323232`)로 감싼다.
- **이유**: 캔버스 배경 자체가 검정(`#000000`)이라, 다크 배경 이미지를 그대로 깔면 이미지 경계가 캔버스와 시각적으로 융합되어 어디까지가 이미지인지 분간이 안 된다. 회색 면을 한 겹 깔면 다크 이미지 가장자리가 회색 면과 대비되어 또렷이 보인다.
- **자동 감지**: 업로드 시 이미지 가장자리 strip(`flowBoard.darkDetection.sampleStripPx`) 픽셀들을 샘플링해 다크 비율을 측정한다.
  - 휘도 < `luminanceThreshold`(기본 30/255)인 픽셀을 "다크"로 카운트
  - 가장자리 픽셀 중 다크 비율 > `edgeRatioThreshold`(기본 0.7) 이면 `isDark = true`
  - 투명(α<128) 픽셀은 카운트에서 제외 — 투명 PNG 로고는 안전하게 false 처리
- **적용**:
  - 캔버스 padding(25) 안쪽에 회색 보드가 들어가고, 회색 보드 자체도 `flowBoard.padding`(25) 만큼 내부 패딩을 갖는다.
  - 회색 보드가 적용된 섹션은 가용 가로폭이 `900 - 50 = 850px`로 줄어든다 → justify 알고리즘이 자동으로 재계산.
  - 라이트 이미지가 같은 섹션에 섞여 있어도 회색 보드 위에서 정상적으로 보이므로 문제 없음 (오히려 톤이 통일됨).
- **꺼야 할 때**: `flowBoard.autoWrapOnDarkImage = false` 로 비활성. 그 경우 검은 이미지는 검은 캔버스에 그대로 깔린다(권장하지 않음).

## 5. 명시적 그루핑 / 복잡한 UI 플로우 — 회색 보드 수동 적용

- **기준**: 다크 배경이 아니어도 한 작업 흐름(예: 진입 → 입력 → 결과 시퀀스, 같은 화면의 상태 변화)을 한 묶음으로 보여줘야 할 때는 회색 보드로 감싸 의미적 그루핑을 시각화한다.
- **이유**: 흐름은 "순서가 있다"는 정보 자체가 의미를 갖는다. 보드로 묶으면 좌→우, 위→아래 순서가 한 묶음 안에서 읽힌다. 장수 기준보다 의미 기준이 우선 — 4~6장 정도여도 "한 시퀀스"임이 분명하면 적용.
- **현재 구현 상태**: 자동 wrap은 4번(다크 배경) 트리거만 구현되어 있다. 명시적 그루핑 wrap이 필요하면 섹션 모델에 `forceWrap` 같은 플래그를 추가하는 확장이 필요(현재는 미구현).

## 6. 캡처 유형별 배치 기준

### 6-1. 모바일 화면 캡처

- **너비**: 300px 고정(또는 280~300px 가변).
- **배치**: 2~3열로 묶어 깔끔하게 정렬. 가로 모바일은 한 행에 2장만 둔다.
- **주의**: 모바일 캡처는 보통 세로로 길어 한 행 높이가 커진다. 같은 행의 다른 이미지가 짧으면 빈 공간이 크게 남으므로, 비슷한 높이끼리 묶는다.

### 6-2. 배너 / 가로 와이드 이미지

- **너비**: 행 전체 너비(보드 안쪽 너비)를 채워도 된다.
- **배치**: 단독 행. 위아래에 다른 이미지를 끼우지 않는다.
- **이유**: 배너는 그 자체가 한 단위 메시지. 옆에 다른 캡처가 붙으면 시선이 분산된다.

### 6-3. 카드 / 컴포넌트 단위 캡처

- **너비**: 280~300px.
- **배치**: 3열까지 채울 수 있다. 같은 종류의 카드를 비교 보여줄 때 유효.
- **이유**: 카드끼리는 비교가 본질이므로, 한 시선 안에 다 들어와야 한다.

### 6-4. 큰 플로우 / 전체 화면 캡처

- **너비**: 행 전체 또는 절반(약 430~450px).
- **배치**: 한 행에 1~2장만. 7장 이상이면 회색 보드로 묶는다.
- **이유**: 전체 화면 캡처는 정보 밀도가 높다. 작게 줄이면 의미가 사라지므로 충분한 크기를 확보한다.

## 부록 — 우선순위

규칙이 충돌할 때는 다음 순서로 판단한다.

1. **의미적 그루핑** — 한 묶음이면 회색 보드, 독립적이면 검은 배경.
2. **판독성** — 너무 작아서 안 보이면 열 수를 줄인다.
3. **세로 길이** — 한 섹션이 너무 길어지면 회색 보드로 묶어 시각적 부피를 줄인다.
4. **수치 규칙** — 위 셋이 모두 OK일 때 `board-rules.json`의 수치를 그대로 따른다.
